# TinyDex

A lightweight, autonomous coding agent harness built in Python. TinyDex implements a deterministic ReAct (Reason + Act) loop using OpenRouter-compatible models to inspect, edit, and execute Python code inside an isolated workspace sandbox.

---

## Architecture Overview

TinyDex functions as an **Agent Harness** that bridges raw LLM reasoning with sandboxed local execution.

* **State & Turn Management:** Maintains multi-turn conversation context across system, user, assistant, and tool execution roles.
* **Execution Dispatcher:** Maps structured tool calls (`tool_calls`) directly to native Python functions and injects safe workspace paths.
* **Security & Containment:** Enforces strict filesystem boundaries to intercept directory climbing (`../`) or absolute path traversal attempts.
* **Deterministic Tool Routing:** Operates with zero temperature and directive system instructions to prevent hallucinated calls or premature termination.

---

## Tool Capabilities

| Tool | Purpose | Security Controls |
|---|---|---|
| `get_files_info` | Lists files, directories, and byte sizes in a given folder. | Blocked from scanning outside the sandbox root using `os.path.commonpath`. |
| `get_file_content` | Reads UTF-8 file contents into memory. | Enforces bounds checking and configurable character truncation limits (`MAX_CHARS`). |
| `write_file` | Writes or overwrites code files in the workspace. | Constrained strictly to valid relative workspace paths. |
| `run_python_file` | Runs scripts and returns `stdout`/`stderr` output. | Executes within the isolated target environment with argument passing. |

## Getting Started

### Prerequisites

* Python 3.10+
* [uv](https://github.com/astral-sh/uv) package manager
* An API key from [OpenRouter](https://openrouter.ai/)

### Installation

1. **Clone the repository:**
   ```bash
   git clone https://github.com/SaintSins/TinyDex.git
   cd tinydex
   ```

2. **Install dependencies:**
    ```bash
    uv sync
    ```

3. **Create environment variables:**
    Create `.env` file in project root:
    ```
    OPENROUTER_API_KEY = your_openrouter_api_key_here
    ```

## Usage

TinyDex operates in two distinct modes depending on how arguments are passed:

### Command Syntax

```bash
uv run main.py [prompt] [--verbose]
```

* `prompt` (optional): A one-shot query. If omitted, TinyDex starts the interactive REPL.

* `--verbose` (optional): Exposes token telemetry, tool execution traces and raw outputs.

1. **Interactive REPL Mode (Default):** Launches a continuous multi-turn session in your terminal that preserves conversation history and tool inspection context in RAM across prompts.

```bash
# Standard interactive session
uv run main.py

# Interactive session with verbose tracing
uv run main.py --verbose
```

* Type prompts directly at `You >` prompt.

* Type `exit` or `quit` to end the session.

* **Single Task Execution Mode:** Executes a one-shot query, running through the tool ReAct cycle until resolution and exiting immediately.

```bash
# Standard one-shot query execution
uv run main.py "what are the contents of lorem.txt"

# One-shot query execution with verbose tracing
uv run main.py "what are the contents of lorem.txt" --verbose
```

## Verbose Output Tracing (`--verbose`)

Adding `--verbose` exposes the inner mechanics of TinyDex's ReAct cycle in real time. It prints step-by-step telemetry, detailing inbound/outbound token usage, tool dispatching, and output interception before the model responds.

### What `--verbose` Displays

1. **Token Telemetry:** Tracks context accumulation and output generation per round-trip:

  ```text
    ↳ Tokens: 637 in | 25 out
  ```

  * `in`: Cumulative inbound prompt tokens (system instructions, conversation history, and tool JSON schemas).

  * `out`: Completion tokens generated by the model (reasoning, function parameters, or final text).

2. **Tool Call Dispatch:** Identifies the function selected from tools.py along with its parsed JSON arguments:

```bash
⚙ Tool Call: get_file_content({'file_path': 'lorem.txt'})
```

3. **Tool Observation Preview:** Displays a preview of the raw string returned from sandboxed environment:

```bash
└─ Output: wait, this isn't lorem ipsum
```

4. **Initial Prompt Reflection:** In single-task mode, echoes the initial user query before starting the loop.

### Examples:

* **Interactive REPL Mode:**

```bash
uv run main.py --verbose
```

**Output:**

```bash
╭──────────────────────────────────────╮
│ TinyDex Interactive Workspace        │
│ Type 'exit' or 'quit' to end session │
╰──────────────────────────────────────╯

You > what are the contents of lorem.txt
  ↳ Tokens: 637 in | 25 out
⚙ Tool Call: get_file_content({'file_path': 'lorem.txt'})
  └─ Output: wait, this isn't lorem ipsum
  ↳ Tokens: 867 in | 65 out

TinyDex >
The contents of lorem.txt are:

  wait, this isn't lorem ipsum

You > exit
Ending session.
```

* **Single Task Execution Mode:**

```bash
uv run main.py "what are the contents of lorem.txt" --verbose
```

**Output:**

```bash
Prompt: what are the contents of lorem.txt
  ↳ Tokens: 810 in | 41 out
⚙ Tool Call: get_file_content({'file_path': 'lorem.txt'})
  └─ Output: wait, this isn't lorem ipsum
  ↳ Tokens: 889 in | 92 out

Final Response:
The contents of lorem.txt are:

  wait, this isn't lorem ipsum
```
